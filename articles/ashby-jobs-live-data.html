Sourcing Live AI Hiring Signals Directly from Ashby Feeds

TL;DR: Pull live, normalized job data straight from Ashby's public posting API across 140 verified boards (6,961 open roles). Pay $0.003 per job record delivered, track exact openings and closures through dataset diffs, and note that company stays null.

Where AI Hiring Happens and Why Direct Feeds Win

Every hiring market coalesces around a central system where its pace-setting employers run recruiting. Across technology, and especially in AI, that centre of gravity is increasingly Ashby. OpenAI, Cohere, Perplexity, Cursor, Harvey, Ramp, Notion, and Linear all run their career boards on Ashby, and their hiring shifts are watched as industry signals. Buyers who rely only on generalist job boards discover these roles late, filtered through a third-party index, and lose the underlying detail. Pulling Ashby's feeds directly surfaces the exact listings shown on each company's own careers page at the moment they go live.

Job data reaches buyers through three paths—indexed databases, page scrapers, and live ATS pulls—and the gap between them widens wherever hiring moves fastest. An index is only a snapshot: it keeps postings that closed yesterday while missing roles opened this morning because its crawler has not come back around. A page scraper fetches HTML at run time, yet breaks whenever an employer redesigns its careers site and only covers companies with custom parsers. A live ATS pull queries the employer's own system directly, returning the exact openings currently live on the careers page—and dropping closed roles the moment they disappear from the feed.

Our Ashby Jobs — Live API Actor queries Ashby's official public posting API for a list of company boards and returns every open role normalized into one schema at $3.00 per 1,000 job results. When you run the same board list again tomorrow and compare the two datasets, new records represent genuine openings and vanished records represent real closures rather than crawl artefacts. For teams building AI job boards, competitor watchlists, or market trackers, that diff is the core product: a board that never lists a closed role earns applicant trust, and a watchlist that flags a rival's new AI-research role the day it appears is actionable. How Buyers Turn Live Ashby Diffs into Product and Pipeline

Because the Actor ships with a pre-verified default pack of 140 Ashby boards holding 6,961 open jobs—concentrated in AI labs, AI infrastructure, GPU cloud, and developer tools alongside fintech, health-AI, security, SaaS, data and analytics, and recruiting tech—different buyers put the same live stream to work in distinct ways:

  • AI job boards and newsletters: A niche AI board does not need the entire web; it needs complete, current coverage of the employers defining the sector. The 140-board pack supplies that baseline, and the daily dataset diff automatically generates "new roles this week" without manual curation.
  • Recruiting and talent intelligence: Employer-maintained department, team, and location fields reveal where a competitor is investing long before any press release. A sudden hiring surge in a rival's research team signals strategy; the same surge at a prospect indicates active budget and an immediate problem to solve.
  • Market research: Live postings paired with full description text support skills analysis, remote-policy tracking, and hiring-velocity measurement across AI on a reliable time series, since timestamps originate from the employer's own ATS.
  • Lead generation: Companies hiring aggressively are companies buying software and services. Filtered by department, live openings work as a targeted buying-signal feed—engineering hiring points to engineering-tool buyers, while sales hiring points to sales-tool buyers.

Inside the Schema: Sample Output and Honest Field Gaps

Because every record comes straight from the ATS the employer maintains, the schema carries the employer's own fields: job title, department, team, employment type, workplace type (Remote, Hybrid, or OnSite), structured location broken out into city, region, and country, posting date, application URL, and the full description text—always included with no second pass required. That structured location breakdown is a meaningful advantage over Greenhouse, whose feeds lack the same granularity; workflows that filter by geography classify Ashby listings cleanly without parsing free text.

Two honest gaps belong alongside those strengths because they govern how downstream pipelines should read the output. First, Ashby's public posting feed carries no company display name: the company field is always null, and the board slug in companyId serves as the identifier (such as openai, ramp, or linear). Second, Ashby carries no language or experience-level field, so both return null rather than being guessed from description text. We return strictly what the source provides.

How We Verified the 140-Board Pack and Manage List Operations

Because a board slug alone does not prove which company owns it, treating companyId as the primary key makes list verification essential. When we built the default pack, we probed 639 candidate board slugs against the Ashby posting API across 3 rounds; 141 returned live jobs. Because Ashby feeds carry no company display name, we verified identities against job content. One board had to go: crisp was a Dutch grocery-delivery company, not the chat platform of the same name—a name collision we only caught by reading the postings. Meanwhile, two similar slugs were both real and both kept: runway is the business-planning platform while runway-ml is Runway AI video. That left exactly 140 boards holding 6,961 open jobs.

Three operational behaviors shape how the pack runs in production:

  1. Ascending sort order and the default cap: The default pack is ordered by open-job count ascending, so a capped default run samples broadly across smaller boards before hitting mega-boards—otherwise OpenAI alone at 876 open roles would consume the whole run. The default cap is 500 records; raise the cap or narrow the board list when you want to exhaust specific companies. You are also not restricted to the default pack: pass any Ashby board slugs in the companies input to pull custom targets.
  2. Pack decay and migration detection: Companies switch ATS providers and board slugs go dark over time. The default pack is re-verified at every version build, and any board that fails during a run is reported in the run summary rather than silently dropped. That same behavior helps on custom watchlists: when a previously active company flatlines to zero postings, it is the signature of an ATS migration.
  3. Single-ATS focus by design: This Actor queries Ashby only. If a target company runs Greenhouse, it belongs in our sibling Greenhouse Jobs — Live API Actor, or in the multi-system parent Career Site Jobs — Live ATS API, which spans all five platforms on the same underlying engine.

Picking the Right Cut: Ashby, Greenhouse, or Multi-ATS

Buyers tracking mixed company lists often ask whether to run the Ashby-only Actor, the Greenhouse-only sibling, or the multi-system parent. Because all three share one engine and one price ($3.00 per 1,000 jobs), the decision depends strictly on your company list and the fields you need rather than tool differences.

Ashby records provide structured city, region, and country fields, team, employment type, and workplace type as first-class attributes, plus full description text on every role. Greenhouse records carry the company display name that Ashby feeds lack, alongside their own structural conventions. If your entire target list runs on Ashby, the single-system Actor keeps inputs compact, tunes defaults to Ashby, and formats run summaries in Ashby terms. If your list spans multiple platforms—or if you want continuity when a tracked company migrates between systems—use the multi-system Career Site Jobs — Live ATS API, which normalizes all five platforms into one schema without changing tooling. For AI-focused products specifically, our B3 pack build showed that the AI startup cohort has consolidated onto Ashby and Greenhouse, with no AI-startup boards returning live postings on Lever or SmartRecruiters—meaning the two single-system Actors plus the parent cover the AI hiring universe in practice.
